### 1. 游戏内播放控制快捷键

全局快捷键直接控制正在跟随的 PotPlayer，不需要 Alt+Tab 回播放器。

- 暂停 / 继续
- 回到这一句开头（重听）：跳到当前字幕的开始时间；当前没有字幕时跳到上一句
- 后退 / 前进若干秒（秒数可设置）
- 可选：在 PotPlayer 画面上显示操作提示（OSD）

调研状态：**可行**，见下方「调研记录 2026-10-08」。已实现（默认快捷键最终为 `Ctrl+Alt+K` 播放 / 暂停、`Ctrl+Alt+↓` 重听、`Ctrl+Alt+←/→` 后退 / 前进）。

### 2. 回看错过的上一句

游戏中忙不过来时漏看的字幕可以找回。

- 快捷键临时把上一句（连按则继续往前）显示几秒，不影响播放
- 简洁模式中显示最近几句的列表
- 已定：回看显示在当前字幕上方（0.82 倍字号 + 「上一句」标签），不替换当前句；快捷键 `Ctrl+Alt+↑`

### 3. 按游戏自动切换字幕位置

不同游戏的 HUD 布局不同（底部可能是对话框或技能栏），字幕需要放在不同位置。

- 按前台程序（如 `xxx.exe`）分别记住字幕位置与宽度，切到对应游戏自动使用
- 没有单独记录的程序使用默认位置
- 已定：编辑模式中用「用于：所有程序 / xxx.exe」显式选择；管理入口在「设置 → 行为 → 按程序的字幕位置」

## 调研记录

### 2026-10-09：其他播放来源——可行，暂不实现

**结论**：mpv 和 MPC-HC / MPC-BE 都能做到与 PotPlayer 相当的体验（完整路径、毫秒进度、跳转与播放控制）；VLC 能做但进度精度差；SMTC、浏览器、媒体服务器等来源拿不到文件路径或精度不足，只适合降级支持。本轮只做了资料调研，下表中的协议细节**均未实测**，实现前需逐个装机验证。

**一个来源要满足的条件**（对照 `PlayerBridge`）：

1. 当前文件的完整路径（用来找同名外挂字幕；拿不到就只能手动选字幕）
2. 毫秒级播放进度与播放状态（现在每 50ms 轮询一次）
3. 控制：跳转、播放 / 暂停、下一关键帧 / 逐帧（重听、前后跳依赖它们）
4. 区分多个实例，并能拿到播放器进程的 pid（前台程序识别要忽略播放器）

**候选来源**：

| 来源 | 接入方式 | 路径 | 进度精度 | 控制 | 用户需要的设置 | 评价 |
|---|---|---|---|---|---|---|
| mpv（含 mpv.net 等 mpv 前端） | JSON IPC 命名管道，读 `path` / `time-pos` / `pause` / `duration`，可 `observe_property` 推送 | ✅ | ✅ 亚毫秒 | ✅ seek / pause / frame-step | `mpv.conf` 里加 `input-ipc-server` | 首选：协议公开稳定、能力完整；窗口类名 `mpv` |
| MPC-HC / MPC-BE | 内置 Web 接口（默认端口 13579）：`/variables.html` 给 filepath、position(ms)、duration、state；`/command.html` 发 wm_command | ✅ | ✅ 毫秒 | ✅ 播放 / 暂停 / 跳转 / 逐帧 | 在选项里开启 Web 接口（可限本机） | 很推荐：用户多；窗口类名 `MediaPlayerClassicW`；seek 参数格式待验证 |
| MPC-HC `/slave` API | `WM_COPYDATA` 双向消息 | ✅ | ✅ | ✅ | 必须由本应用以 `/slave` 启动播放器 | 不能附着已打开的实例，不采用 |
| VLC | Lua HTTP 接口 `/requests/status.json`、`playlist.json` | ✅（playlist 的 uri） | ⚠️ VLC 3 的 `time` 为整秒，`position` 为比例，需本地时钟插值、在秒跳变时校准 | ✅ seek / pause | 开启 Web 接口且必须设密码 | 能做但同步精度差；想精确要自写 Lua 接口脚本，用户部署更麻烦；VLC 4 精度待查 |
| Kodi | JSON-RPC：`Player.GetProperties`（时间含毫秒）、`Player.GetItem`（文件） | ✅ | ✅ | ✅ | 允许 HTTP 远程控制 | 技术合适，Windows 用户少，优先级低 |
| 系统媒体传输控制（SMTC）：Windows 媒体播放器、电影和电视、浏览器、UWP 应用 | WinRT `GlobalSystemMediaTransportControlsSessionManager` | ❌ 只有标题 | ⚠️ 只给「位置 + 更新时刻」快照，需外推，各应用更新频率不一 | ✅ 视应用支持 | 无 | 覆盖面最广；无路径、精度不稳；Node 调 WinRT 需原生模块或辅助进程 |
| 网页视频（B 站、YouTube 等） | 浏览器扩展读 `video.currentTime`，经本地 WebSocket 推送 | ❌ URL / 标题 | ✅ | ✅ | 安装扩展 | 精度好，但相当于另一个子项目，字幕需手动指定 |
| Jellyfin / Emby / Plex | 服务器 Sessions API | ✅ 服务器端路径 | ❌ 客户端约 10 秒上报一次 | 部分 | 服务器地址与令牌 | 精度太差，不建议；Jellyfin Media Player 内核是 mpv，可能可走 mpv IPC（待验证） |
| KMPlayer、GOM、SMPlayer 等 | 无公开远程接口（SMPlayer 内部 mpv 能否接入待查） | — | — | — | — | 基本做不了，只能看 SMTC 能否覆盖 |
| 手动时钟（不接播放器） | 手动选字幕，快捷键开始 / 暂停，手动对齐偏移 | 手动 | 取决于对齐 | 只控制本应用 | 无 | 万能兜底，实现最简单 |

**若重新启动，需要的架构调整**：

- 实例标识从 `hwnd` 改为通用 `id`，附带 `pid` 和来源类型
- 读进度改为异步（HTTP、命名管道都是异步），最好由 bridge 主动推送 tick（mpv 订阅即推送，PotPlayer 在内部继续轮询）
- 能力声明：有无路径、精度等级、能否跳转 / 逐帧；把 `command(POT_CMD_NEXT_KEYFRAME)` 这类 PotPlayer 专有调用换成语义化的 `stepFrame()` 等，界面按能力隐藏不支持的操作
- 粗精度来源（VLC、SMTC）要有本地时钟插值层，与 `Controller.checkSeekLanding` 的落点判断分开
- 设置页：启用哪些来源、端口 / 密码 / 管道名，连接失败时给出引导
- QA：`POTSUB_FAKE_PLAYER` 能模拟不同来源；操作真实播放器时同样只控制自己打开的测试实例

**建议顺序**：先抽象接口并以 mpv 验证 → MPC-HC / MPC-BE（Web 接口）→ 手动时钟模式兜底 → 视需求再看 VLC、SMTC / 浏览器扩展。

### 2026-10-08：游戏内播放控制（第 1 项）——可行

**结论**：可以实现。暂停 / 继续、跳转都能通过 PotPlayer 的窗口消息完成，不需要激活 PotPlayer 窗口，也不抢游戏焦点。唯一要处理的是 PotPlayer 默认开启的「以关键帧定位」：视频跳转会落到前一个关键帧。

**测试方法**：用 `PotPlayerMini64.exe /new <文件>` 另开一个最小化实例，只向标题含测试文件名的窗口发消息，不碰正在使用的播放器；测试结束后强制结束该实例，PotPlayer 的注册表设置（`HKCU\Software\DAUM\PotPlayerMini64\Settings`）前后没有变化。测试文件：

- 合成视频（H.264，480×270，每 10 秒一个关键帧）
- 真实番剧片段（从媒体库剪出前 4 分钟视频流，HEVC 10bit 1080p，关键帧间隔 1–10.4 秒，平均约 4.5 秒）
- 静音 WAV

**消息接口**（`WM_USER` = 0x400，`wParam` 为命令，`lParam` 为参数；定义见 PotPlayer SDK 头文件，例如 [ld3l/PotPlayerControl `InternalSimpleCmd.h`](https://github.com/ld3l/PotPlayerControl/blob/main/InternalSimpleCmd.h)）：

| 命令 | 值 | 用途 | 实测 |
|---|---|---|---|
| `POT_SET_CURRENT_TIME` | 0x5005 | 跳到指定毫秒 | 可用，`PostMessage` 即可；精度见下表 |
| `POT_SET_PLAY_STATUS` | 0x5007 | 0 切换 / 1 暂停 / 2 播放 | 3–17ms 生效；对已在播放的再发 2 无副作用 |
| `POT_SET_SPEED` | 0x5016 | 播放速度 200–12000 | 未测，备用 |
| `POT_SEND_VIRTUAL_KEY` | 0x5010 | 模拟 PotPlayer 内的按键 | 可用，但结果取决于用户的快捷键设置，不采用 |
| `POT_SET_SHOW_MESSAGE` | 0x6040（`WM_COPYDATA`） | 在 PotPlayer 画面上显示提示 | 未测；游戏时 PotPlayer 在后台看不到，操作反馈应显示在本应用的字幕窗口里 |

PotPlayer 的菜单命令也可以用 `WM_COMMAND` 发送（ID 取自 `PotPlayer64.dll` 的菜单资源 101）：10014 播放/暂停、10059/10060 步退/步进、10786/10787 上一/下一关键帧、10244/10245 上一/下一对白、10582 当前字幕起点、10265 切换「以关键帧定位」。对白相关命令依赖 PotPlayer 自己加载的字幕，不如用本应用解析出的时间轴可靠，不采用。

**跳转精度**（暂停状态下跳转后读回的位置 − 目标位置）：

| 文件 | 以关键帧定位：开（PotPlayer 默认） | 以关键帧定位：关 |
|---|---|---|
| 合成视频（10s GOP） | 落到前一个关键帧，最多早 10 秒 | 0ms，约 80–280ms 完成 |
| 真实番剧 HEVC | 早 0.6–3.2 秒 | 0ms，约 95–425ms 完成 |
| WAV 音频 | 0ms | 0ms |

- 「以关键帧定位」开启时，向前跳 5 秒可能原地不动或只前进 2 秒；补发「下一关键帧」（10787）后变成 +5.9 秒 / +10.4 秒，能用但不精确。
- 向后跳和「重听这一句」只会落得更早，不影响使用（多听一两秒）。
- 音频文件（音声、ASMR 等）不受影响，始终精确。
- 该设置位于 PotPlayer 右键菜单「播放 → 定位 → 以关键帧定位」，或选项中的「如存在关键帧数据则以关键帧为移动单位」。用 `WM_COMMAND 10265` 只能切换、无法读取当前状态，不应由本应用去改用户的播放器设置。

**实现要点**：

- 命令发给当前正在跟随的实例，统一用 `PostMessage`（不阻塞主进程，不重入）；跳转后由现有的 50ms 轮询读回新位置。
- 「重听这一句」：目标 = 当前字幕开始时间 − 本文件偏移（再提前约 200ms）；当前没有字幕时用上一句。连按时基于目标位置继续往前，而不是基于尚未刷新的当前位置。
- 运行时检测关键帧定位：跳转后实际位置比目标早超过约 500ms，就认为开启了关键帧定位，在设置页提示用户可在 PotPlayer 中关闭；向前跳落在原位置之前时补发 10787。
- 操作反馈（如“⏪ 重听”“已暂停”）显示在字幕窗口内，因为 PotPlayer 被游戏遮住。
- 已定：默认快捷键见上；后退 / 前进默认 5 秒，可选 2 / 5 / 10 / 30 秒。
- 补充（实现时实测）：跳转期间 PotPlayer 的读数不可靠——旧位置冻结或继续走、返回请求的时间本身、临时的 0、状态“已停止”；最小化或被遮挡时读数约 0.5 秒才更新一次。落点必须以第一个可靠读数为准，不能按固定延时读取。`WM_COMMAND 10787` 在播放中也可用。
