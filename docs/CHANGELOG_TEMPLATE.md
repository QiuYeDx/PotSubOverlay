# 变更日志模板

复制下面的结构到项目根目录的 `CHANGELOG.md`，每次发布或合入用户可见的改动时补充对应版本。

## 规则

- **每个版本一个条目**，标题必须是 `## [x.y.z] - 日期或说明`：应用内的更新弹窗按这个格式解析远程 CHANGELOG，`corepack pnpm changelog:check` 也会检查 `package.json` 的当前版本是否有条目。
- 尚未发布的版本可以写成 `## [x.y.z] - 开发中（更新于 YYYY-MM-DD）`，发布时改成发布日期。
- 新版本写在最上面；分组用 `### 分组名`，条目用 `- ` 开头，一条说清一件用户能感知的事。
- 写“改了什么、对用户有什么影响”，而不是“改了哪个文件”；修复写清楚原来的症状。
- 只出现在实际做过的分组，没有内容的分组不写。

常用分组（按需选用，保持这个顺序）：

| 分组 | 写什么 |
|---|---|
| 新增 | 新功能、新页面、新设置项 |
| 优化 | 现有功能的体验、性能、默认值调整 |
| 修复 | 缺陷修复，写清原来的症状 |
| 安全与隐私 | 权限、数据处理、依赖安全更新 |
| 测试与文档 | 测试、README、设计文档、开发工具 |
| 依赖 | 运行时或重要依赖的升级 |
| 已知限制 | 本版本仍存在、用户需要知道的限制 |

---

```markdown
# Changelog

本项目的所有重要更改都将记录在此文件中。格式参考 [Keep a Changelog](https://keepachangelog.com/zh-CN/1.1.0/)，版本号遵循 [语义化版本](https://semver.org/lang/zh-CN/)。

## [0.2.0] - 开发中（更新于 YYYY-MM-DD）

### 新增

- 

### 优化

- 

### 修复

- 

## [0.1.0] - YYYY-MM-DD

### 新增

- 初始版本。
```
